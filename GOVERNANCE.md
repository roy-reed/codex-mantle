# Governance

Codex Mantle starts with a maintainer-led governance model. The repository owner is the initial
maintainer and final decision maker while the project establishes a contributor community.

## Decision process

Routine fixes are decided in pull-request review. Changes to transaction safety, compatibility
gates, remote exposure, plugin execution, credentials, release policy, or governance require a
written rationale, focused tests, and explicit maintainer approval. Maintainers prefer documented
consensus; when consensus is unavailable, the responsible maintainer records the decision and
trade-offs in the pull request.

## Maintainers

Maintainers review and merge changes, triage security reports, cut releases, and protect project
boundaries. New maintainers may be added after sustained, trustworthy contributions across code,
review, tests, and community support. Removal requires inactivity, resignation, or a documented Code
of Conduct or security concern. Changes to the maintainer set are made by pull request to this file.

## Releases and ownership

Only maintainers may publish releases or change protected repository settings. Contributions remain
under Apache-2.0; no contributor gains ownership of user data, private configuration, or trademarks
by participating.
